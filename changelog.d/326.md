### AI clients: allow runs on any non-production target for the session ([#326](https://github.com/filipac/runlet/issues/326))

- **The problem:** when an AI client debugged through `run_php`, every run on a local project, Docker application, or SSH host showed the approval sheet. "Allow for this session" existed only for the Laravel sandbox.
- **Now:** the sheet offers **Allow runs on** *target* **from** *client* **for this session** on every target that isn't production. Tick it and press Run, and that client's later runs on that target go ahead without a sheet until the client disconnects or Runlet quits.
  - **Per target, per client:** allowing one target allows nothing on another, and nothing for another client.
  - **Production always asks,** with its warning, and never offers the allowance. A target that is edited, removed, or marked production asks again.
  - **SSH:** an allowed host skips the sheet only while it is connected. A host that isn't connected asks (approving connects), and one that needs a login is still refused.
- **Settings ▸ AI Clients** lists each client's allowed targets; **Revoke** ends them all. The Connection Manager's AI client rows list them too.
- `list_targets` says which targets can be allowed for the session, and a run's note in its tab says when it ran because of the allowance.
