### Renaming a tab focuses its name with the whole title selected, in both tab layouts ([#285](https://github.com/filipac/runlet/issues/285))

- **The bug:** renaming a tab turned its title into a text field that nothing focused. In the
  vertical tabs the field never got the keyboard, so renaming didn't work at all; in the tab bar
  you had to click into it, and typing went into the old title instead of replacing it.
- **Now:** one rename field for the tab bar, the vertical tabs, and pinned tabs in both, so they
  behave the same:
  - **Starting a rename** (a double-click on the tab, Rename… in its context menu, Window ▸
    Rename Tab…, the command palette, or Open Anything, which now lists Rename Tab… for "rename")
    gives the field the keyboard with the whole title selected, so typing replaces it.
  - **Return** renames the tab, **Esc** keeps the old title, and **a click elsewhere** (the
    editor, another tab, an empty part of the tab bar) renames it, as in Finder. An empty or
    whitespace-only name keeps the old title.
  - **While renaming,** keys go to the field and never to the editor, Esc does nothing else (it
    doesn't hide the output pane), and ⌘W closes nothing. Afterwards the editor gets the keyboard
    back.
  - **From the palettes:** the field takes the keyboard only once the palette has closed and given
    its window the keyboard back, and takes it back if code grabs it right after the start.
- Debug builds have the steps `rename-begin`, `rename-state`, `rename-type`, `rename-key`, and
  `rename-blur`; `scripts/tab-rename-check.py` checks every way in, both layouts, and pinned tabs
  with scratch data, and takes the screenshots.
